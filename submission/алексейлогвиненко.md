## 1. Цель

Развернуть Minecraft-инфраструктуру из двух контейнеров:
- `velocity` (proxy) с внешним доступом на `25565`;
- `paper` (backend) на `25570` только внутри docker-сети.

Требования:
- backend не должен быть доступен с хоста напрямую;
- мир и конфиги backend должны сохраняться между перезапусками;
- в MOTD должен быть указан ник;
- нужно подтвердить работу проверками.

## 3. Реализация в моем проекте

Использована конфигурация с двумя сервисами:
- `paper` (backend);
- `velocity` (proxy).

Ключевые моменты:
- опубликован только прокси-порт `25565`;
- backend работает только внутри docker-сети;
- данные backend сохраняются через маунт в локальную папку;
- в `server.properties` выставлены обязательные параметры:
  - `motd`
  - `online-mode=false`
  - `server-port=25570`
  - `query.port=25570`

## 4. Проверка

Команды:

```bash
docker compose up -d --build
docker compose ps
python mc_motd_retriever.py localhost 25565
python mc_motd_retriever.py localhost 25570
```

Ожидаемая интерпретация:
- `25565`: сервер отвечает, MOTD читается;
- `25570`: прямого доступа с хоста нет (ошибка/таймаут/отказ).
