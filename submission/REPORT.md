# ДЗ22: запуск Minecraft-связки Velocity + Paper 1.16.5 в Docker Compose

## Цель
Собрать и проверить схему из двух контейнеров для Minecraft: `Velocity` как прокси и `Paper 1.16.5` как backend, так чтобы с хоста был доступен только прокси-порт `25565`, а backend работал только внутри docker-сети.

## Что я сделал
Я поднял проект через `docker compose` с двумя сервисами:
- `velocity` (proxy)
- `paper` (backend)

Оба контейнера собраны вручную на базе Ubuntu LTS (`ubuntu:24.04`) из собственных Dockerfile. Готовые minecraft-образы я не использовал.

Для Java-окружения в контейнерах использован GraalVM.

## Почему world-данные хранятся через внешнюю директорию
Для backend я использовал bind mount `./paper/data:/srv/paper`. Это позволяет хранить мир и конфиги вне контейнера. Если контейнер пересобрать или пересоздать, данные мира не пропадут, и сервер поднимется с тем же состоянием.

## Как устроена схема из двух контейнеров
Внутри `docker compose` контейнеры подключены к общей сети `mcnet`:
- `velocity` ходит к backend по адресу `paper:25570`
- `paper` не публикует порт наружу, у него только `expose: 25570`

С хоста открыт только `25565:25565` у прокси. Это и требовалось по заданию: backend доступен только внутри docker-сети, наружу торчит только proxy.

## Обязательные настройки по ТЗ
На backend (Paper 1.16.5) выставлены обязательные параметры:
- `motd=backend сервер happy_end_always`
- `online-mode=false`
- `server-port=25570`
- `query.port=25570`
- `enable-query=true`
- `eula=true`

На proxy (Velocity) включен `ping-passthrough = "all"`, backend указан как `paper:25570`.

## Как я проверял
Я проверил:
- контейнеры в состоянии `Up` (`docker compose ps`)
- доступность `25565` с хоста
- недоступность `25570` с хоста
- ответ MOTD через `mc_motd_retriever.py`

Результат проверки:
- на `25565` приходит нужный MOTD backend
- на `25570` с хоста получаю ошибку/недоступность (что и должно быть)

## Результат
Схема работает корректно: proxy `Velocity` доступен снаружи на `25565`, backend строго `Paper 1.16.5` работает только внутри docker-сети на `25570`, требования ДЗ22 выполнены.

## Небольшое замечание по выводу в терминале
Если при запуске в Windows PowerShell кириллица в логах или выводе местами отображалась некорректно, это связано с кодировкой консоли Windows, а не с работой сервера.

## Вывод
Я собрал и проверил рабочую конфигурацию из двух контейнеров без открытия backend-порта наружу. Проверка подтверждает, что трафик идет через Velocity, а backend из хоста напрямую недоступен.
